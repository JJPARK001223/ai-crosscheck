# 시각화 개편 검수 — Codex

검토일: 2026-11-28. 지정 단계만 수행. HTML·PDF·발표 원본은 읽기 전용으로 열람했으며 수정하지 않았다.

**판정: 시각화 확정본으로는 수정 필요.** 실제 발표 수치·분할·파라미터 계산과 주요 조작은 통과했다. 그러나 누출 비교 그림의 겹침, 예측 비교 그림의 축 제목 잘림, 분할 막대의 대비 부족, 320px 문서 넘침을 직접 재현했다. 개인 학습용 초안의 조건부 사용과 완성본 채택을 구별해야 한다.

## 1. 대상·방법·확인 한계

- 대상: 사용자 지정 폴더의 `AI_Fracture_Mechanics_Study.html`과 같은 이름의 PDF. `_publish.html`은 이번 검사 대상에 포함하지 않았다.
- HTML SHA-256: **`65ce320679cf2a9aaabd417e7c6436e5874398733b8c17132648b0c8afde4cdc`**.
- PDF SHA-256: **`528b703b8ed96888d4129bb6cde98f1deb0390f665c537f4220740a920687b92`**, 총 37쪽.
- `PROBLEM.md`, `codex_review.md`, `codex_review2.md`, `claude_response.md`, 저장소 `AGENTS.md`, 지정 협업 안내문의 관련 내용을 읽었다. 이번은 상호 검수 단계이며 다른 AI·하위 작업자·오케스트레이터·PowerShell 자동화 스크립트는 실행하지 않았다.
- Playwright + **Edge 158.0.4370.45**, 원본 `file:` URL로 직접 실행했다. 최초 브라우저 실행은 `spawn EPERM`이었다. 이후 권한 요청을 거친 실행에서 **Chromium 자체 샌드박스를 켠 채** 검사했다. 테스트용 JS·Python·이미지·로그는 시스템 TEMP에만 저장했다.
- `.viz svg`는 **19개**다. 전역 정의용 숨김 `gdefs`까지 합하면 SVG 요소는 20개다. 19개 전부를 라이트·다크 각각 렌더링해 38개 개별 PNG와 묶음 이미지를 육안 확인했다. 숨김 정의용 SVG는 독립 학습 그림으로 세지 않았다.
- SVG 텍스트의 실제 브라우저 경계 상자와 그림 경계도 비교했다. 이 측정은 글자끼리의 모든 겹침을 자동 판정한 것이 아니며, 겹침은 렌더링과 좌표를 함께 확인했다.
- 원본 21개 SHA-256을 이전 직접 검사 당시 TEMP 목록과 다시 비교해 모두 동일함을 확인했다. 14번 10~13·16장, 16번 6·9~16장의 원본 ZIP/XML을 이번에 다시 읽었다. 11번 5~6장 내장 그림은 해당 원본에서 앞서 만든 렌더링을 다시 직접 보았다. 발표 원문·그림·추출본을 PUBLIC 저장소에 첨부하지 않는다.
- PDF는 Poppler로 **1·2·3·4·15·23·24·27·28·29·30쪽**을 렌더링했다. 주요 그림·한글·표가 있는 1·2·4·15·23·24·27~30쪽을 육안 확인했다. PDF 전쪽 시각 검수, 실제 iPad/iPhone의 Safari, 실제 손가락 제스처, 스크린리더 사용성은 **확인 불가**다.
- 실제 학습 성능 재현, 원자료 분할 재현, Abaqus 실행, GE/EPRI 원표의 검증은 하지 않았다. 아래에서 ‘수치 일치’는 발표와 문서의 일치이며 연구 결과의 독립 재현을 뜻하지 않는다.

## 3. 직접 발견한 시각화 결함

P1은 확정본 채택 전 수정 권고, P2는 가독성·해석·접근성 개선, P3는 경미한 디자인 결함이다. V번호는 이번 시각화 검수 식별자이며 이전 F/N번호를 대체하지 않는다. 변경 전 SVG의 동일 조건 렌더링이 없으므로 모든 V항목이 이번 개편에서 새로 발생했다고 단정하지 않는다.

### V01 — P1: `leakSvg`에서 제목·범례와 데이터가 겹침

- 라이트·다크와 **PDF 27쪽**에서 동일하게 보인다.
- 첫 블록 6번째 결함 행과 둘째 블록의 제목이 같은 높이에 놓인다. `block(18,...)`의 6번째 사각형은 viewBox y=146~160인데 다음 제목은 y=158이다.
- 둘째 블록 6번째 행은 y=286~300이고 범례 중심은 y=298이므로 겹친다. 결함 행 라벨도 제목·범례에 가려진다.
- **조치:** 블록 간 간격과 전체 viewBox 높이를 늘리고 범례를 마지막 행 아래로 옮긴다. 그림 바깥 경계 검사만으로 잡히지 않는 내부 겹침이다.

### V02 — P1: `pfSvg` 아래 축 제목 잘림, kNN 축 제목 일부 넘침

- `pfSvg`는 viewBox 높이 340인데 아래 축 제목 기준선은 y=352다. 실제 1440px 화면에서 SVG 높이 약 471.27px, 제목 경계 하단은 약 491.90px로 **약 20.6px 초과**한다. 렌더링에는 실제값 축 제목이 사실상 보이지 않는다. **PDF 24쪽도 동일**하다.
- `knnSvg`의 세로 축 제목 왼쪽 경계는 SVG보다 약 1.86 화면 px 바깥이다. 잘림 규모는 작지만 양쪽 테마에서 재현된다.
- **조치:** 축 제목·눈금·범례를 포함할 여백을 확보하고 viewBox·축 위치를 함께 조정한다.

### V03 — P1: 분할 막대 글씨의 대비 부족

- `splitSvg` 내부 라벨은 테마와 관계없이 흰색이다. 다크 모드에서는 막대가 밝아져 흰 글씨와 구별이 약해진다.
- 렌더링된 막대 중앙의 글자 없는 배경색을 표본 측정해 흰색과의 상대휘도 대비를 계산했다. Train/Validation/Test 순서로 라이트 약 **5.28/3.81/4.66:1**, 다크 약 **2.72/2.15/2.38:1**이다. CSS 원색·불투명도와도 대응한다. 이는 전체 페이지의 모든 글씨를 대상으로 한 접근성 인증은 아니다.
- 일반 크기 글씨의 비교 기준은 [W3C의 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)의 4.5:1을 참조했다(접근일 2026-11-28). 이 라벨은 모바일에서 더 작게 보인다.
- **조치:** 밝은 막대에는 어두운 글씨를 쓰거나 라벨을 막대 밖의 고대비 영역에 둔다. 실제/가상 배지와 선택 버튼의 다크 모드 흰 글씨도 같은 원리로 함께 점검한다.

### V04 — P1: 320px에서 전체 펼침 시 문서 가로 넘침

- 320px, 라이트·다크 모두 `documentElement.scrollWidth=body.scrollWidth=355`를 측정했다. 모두 접으면 320이다. 390·820·1024px는 접힘/펼침 모두 문서 폭과 일치한다.
- 원인은 **4.3 RAG 구성요소 표**다. `.tw` 내부가 아닌 표의 경계가 x≈46~355.41px, 폭≈309.41px로 화면 밖에 나온다. SVG 내부 스크롤과 별개의 문제다.
- **조치:** 이 표도 폭 제한된 내부 가로 스크롤 컨테이너에 넣거나 좁은 화면에서 열 구성을 바꾼다. F18의 이전 ‘해결’ 판정이 현재 버전·전체 펼침 조건에는 그대로 적용되지 않는다. 발생 시점은 확정하지 않는다.

### V05 — P2: Test 분할 라벨이 좁고 모바일 글씨가 작음

- Test 막대 폭은 전체의 약 10%인 72 viewBox 단위다. 건수·비율 라벨이 막대 양쪽 가장자리에 닿거나 넘는다. 1440px에서 라벨 오른쪽 경계가 SVG 바깥으로 약 0.55px 나가며, PDF 28쪽에서도 끝 문자가 가장자리에 붙는다.
- min-width 600px에서는 720 viewBox의 11.5px 라벨이 화면상 약 **9.6px**, 11px 라벨은 약 **9.2px**가 된다. 스크롤 확보만으로 읽기 크기가 보장되지는 않는다.
- **조치:** 좁은 구간 라벨을 아래로 분리하거나 두 줄·외부 범례로 바꾸고, 핵심 숫자·설명 글씨를 키운다.

### V06 — P2: kNN 거리 범위의 화면 모양이 정규화 거리와 불일치

- 거리 계산은 정규화 좌표의 유클리드 거리로 맞다. 그러나 축 영역은 가로 340·세로 300인데 이웃 범위를 `r=거리×340`인 **화면 원**으로 그린다.
- 두 축이 같은 0~1 범위라 이 거리 집합은 화면에서는 x반경 `거리×340`, y반경 `거리×300`인 타원이어야 한다. 현재 그림은 세로 범위를 약 13.3% 크게 보인다. 선택된 이웃의 계산 결과까지 틀린 것은 아니다.
- **조치:** 타원으로 바꾸거나 축의 가로·세로 배율을 같게 한다. 큰 최원거리는 데이터 희소성 신호이며, 이것만으로 엄밀한 외삽 여부가 결정되는 것은 아니라는 설명도 권한다.

### V07 — P2: 지표 그림의 이상치를 경계로 옮겨 그리는 표시

- `mtSvg`는 예측값을 0~70에 잘라 그리지만 MAE·RMSE·R²는 자르기 전 값으로 계산한다. 기본 화면에도 위쪽 경계에 붙은 점이 보인다. 히스토그램도 ±26 밖 오차를 가장자리 bin으로 모은다.
- 수치 계산 오류는 아니다. 그러나 범위 밖 점·초과 bin임을 표시하지 않으면 ‘표시된 좌표로 계산한 지표’라고 오해할 수 있고, 이상치 효과를 설명하는 그림에서 특히 불리하다.
- **조치:** 자동 축 확장, 범위 밖 화살표/점 모양, 초과 개수·bin 표기를 넣는다. `pfSvg`의 상한 자르기 등에도 같은 규칙을 적용한다.

### V08 — P2/P3: 작은 표기·스타일 불일치

- `jcSvg` 범례의 제외 표식은 회색 **사각형**인데 실제 제외 데이터는 속 빈 원이다. ‘제외(속 빈 점)’ 설명과 범례 심벌을 맞출 필요가 있다(P2).
- `layerSvg`의 화살표 라벨이 카드 경계에 가깝고, 선택하지 않은 카드·설명에는 opacity가 더해져 작은 글씨의 가독성이 낮아진다. 주된 흐름은 읽히지만 확대·모바일 가독성을 개선할 필요가 있다(P2).
- `omniSvg` 카드가 정의되지 않은 `--ac` 색 변수를 사용한다. `card`에 전달한 색과 `gid` 규칙도 맞지 않아 상단 띠가 검게 렌더링된다. 콘솔 오류 없이 생기는 스타일 오류다(P3).

| kNN 가로 스크롤 후 | 컨테이너를 오른쪽으로 200px 이동한 뒤 다른 위치를 터치해 약 (0.73,0.68)로 갱신됨을 확인했다. 좌표에 내부 스크롤이 이중 적용되는 오류는 관찰하지 못했다. |

| 인쇄 CSS | print 매체에서 `.dot,.pp` 40개가 모두 `display:none`이다. 정적 데이터 점은 `.dot`이 아니므로 유지된다. PDF 2·15쪽의 흐름도/RAG에서도 이동점·재생 버튼이 숨겨지고 카드·화살표는 남는다. |

**과학적 해석:** 구조 설명 배지와 RAG의 색인/질의 구분은 유효하다. 움직이는 점은 실제 패킷·샘플의 측정된 이동 속도·지연·실행 순서를 재현하지 않는다. 카드 위를 점이 통과하는 방식도 개념적인 방향 표시다. ‘실제 처리 시간·병렬성·실데이터를 나타내지 않는 개념 애니메이션’이라고 한 문장 보강하면 오해가 줄어든다. 현재 상태가 데이터 흐름을 실측했다고 주장하는 것은 아니므로 숫자 오류와 같은 등급으로 보지는 않는다.

**균열 성장 해석:** a/t를 450ms마다 0.05씩 늘리고 상한 뒤 다시 초기화하는 순환이다. Paris식, 하중 이력, 사이클 수, 재료·환경을 계산하지 않는다. 버튼·그림에 개념도라고 명시해 실제 성장 곡선으로 제시한 오류는 발견하지 못했다. 반복 초기화가 치유·물리적 역성장으로 오해되지 않도록 ‘시간·사이클과 무관한 형상 변화’와 재시작 표시를 권한다.

**접근성 한계:** 재생 버튼은 실제 HTML 버튼이라 키보드 조작이 가능하다. 층/RAG는 SVG 클릭 외에 HTML 버튼도 있다. kNN 질의 좌표는 포인터 클릭만 있고 좌표를 키보드로 바꾸는 입력은 없어 동등 조작 수단을 보완할 필요가 있다. 깜박임·발작 안전성의 정량 인증이나 스크린리더 전달 품질은 확인 불가다.

아래는 CSS viewport 기준이며 라이트·다크에서 같은 결과였다. 접힘/펼침은 모든 `details`를 대상으로 했다.

- 육안 확인한 PDF 쪽에서 한글이 정상으로 보이며 검은 네모·다른 글리프 치환은 발견하지 못했다. 텍스트 추출만으로 판정하지 않고 PNG를 직접 보았다.

- 1→2쪽 흐름도처럼 제목과 그림이 다른 페이지에 놓이는 경우가 있다. 그림 전체가 사라진 것은 아니지만 인쇄본에서는 제목·본문·그림을 함께 묶는 페이지 나눔을 개선할 수 있다.
