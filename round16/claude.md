# Round 16 — Claude Blind 조사

## A. 통합 발표 흐름 설계

벤치마크(염희건 J-적분 자료)의 패턴은 "배경(짧게, 각주多) → 목표(Part 분할) →
모델/Case → FE형상·BC(치수표+스케치) → 하중조건(이론식+FE보정 절차) → 해석조건
(메시·요소·수렴성) → 결과추출 타당성(이상치 제외 근거) → 결과그래프(2종 스케일) →
결론"이다. 이 순서는 "청중이 왜 이 모델을 믿어도 되는지"를 결과를 보여주기 **전에**
확신시키는 구조다 — 수식 이론을 길게 설명하기보다, 모델 설정의 타당성 검증에 분량을
할애한다.

사용자가 가진 4개 문서를 이 틀에 매핑하면 다음과 같다:

| 벤치마크 단계 | 사용자 기존 문서의 어느 부분 | 비고 |
|---|---|---|
| 연구배경 | 선행연구1·3 뼈대의 SLIDE1(배경)+SLIDE12(Case B 1장 요약)을 **압축** | 뼈대 원본은 4개 재료군(A~D) 전체를 다루므로, 본인 발표에는 Case B(균열/시멘트페이스트)만 남기고 나머지는 "같은 틀이 다른 재료에도 적용된다"는 1줄 각주로 축소 |
| 연구목표 | (신규 작성 필요 — 기존 문서 어디에도 없음) | Part1: 3D FE로 K 추출절차 확립(Abaqus 상호작용적분) / Part2: 선행연구3 식(3)(4)로 Υ·파괴하중 예측, 논문 절차(2D 곡선맞춤)와의 수치기법 차이 명시 |
| 이론적 모델(식) | 이론정리 3-1.1~3-1.2(근접균열단 FE응력 무효화, K-지배영역 곡선맞춤) + 선행연구3 식(3)(4) | **주의**: 사용자 본인은 곡선맞춤이 아니라 상호작용적분을 썼으므로, 이 절은 "논문이 쓴 방법"으로 명확히 라벨링하고 본인 방법은 별도 절로 분리(아래 B 참조) |
| FE 형상·BC | 현재 어떤 문서에도 치수표·스케치가 없음(아래 C에서 gap으로 지적) | 3점굽힘 시편 치수(지간, 폭 H, 균열깊이 a), 재료물성(E, ν) 표 신규 필요 |
| 하중조건 | FE해석결과 분석 §2(K-P 선형성, K/P=0.4793) | 벤치마크의 "이론식 보정" 슬라이드 패턴과 동일하게, 선형탄성 중첩원리 검증을 이 단계에 배치 |
| 해석조건 | FE해석결과 분석 §3(Contour_1 제외 근거, Abaqus 공식문서 인용) | 요소타입(C3D20), contour 8개, 21개 crack-front 위치, element/node 수는 Abaqus .dat/.cae에서 추출 필요(이론정리·결과분석 문서 어디에도 숫자가 없음) |
| 결과추출 타당성 | FE해석결과 분석 §3 전체 | 벤치마크 패턴과 완전히 일치 — 추가 작업 불필요, 재배치만 필요 |
| 결과그래프 | FE해석결과 분석 §4(가장자리-중앙 7.8%) | 현재 텍스트 서술만 있고 실제 그래프/스크린샷이 없음(아래 C) |
| 결론 | FE해석결과 분석 §5(Υ 보정 다음단계) | 그대로 사용 가능 |

**이론(선행연구1·3 전체 틀) vs 배경 설명 분량 판단**: 벤치마크는 통상 이미 알려진
공학 기준(ASME, 보 이론)을 배경으로 쓰므로 짧게 각주 처리하지만, 2-조건 통합파괴기준은
청중(랩 동료)에게도 생소한 **사용자 고유의 이론적 전제**이므로 벤치마크처럼 2쪽으로
압축하면 안 된다. 다만 선행연구1·3 뼈대 전체(4개 재료군, 22개 식)를 다 보여줄 필요는
없고, 사용자 발표의 "배경"은 "조건1·2란 무엇인가(식1·2)" + "왜 균열 사례(Case B)에서는
조건2가 지배적인가"만 3~4슬라이드로 압축하는 것이 적절하다 — 뼈대 문서의 SLIDE3·4
(조건1·2 식 상세)를 재사용.

## B. 수식 유도·그림·모델링의 배치

1. **곡선맞춤(논문 방법) vs 상호작용적분(본인 방법)의 구분**: 이론정리 3-1.2의
   곡선맞춤 유도는 "논문 §4.3이 쓴 방법"이라는 라벨을 달고 배경/이론 설명 단계에서
   1회만 보여준 뒤, "본인은 Abaqus 상호작용적분(domain integral)으로 직접 K를 얻었다"는
   문장과 함께 **해석조건 단계**로 넘어가야 한다. 두 방법을 같은 슬라이드에서 섞어
   설명하면(예: 곡선맞춤 수식 바로 아래에 본인의 상호작용적분 결과표) 청중이 "본인이
   실제로 곡선맞춤을 수행했다"고 오해할 위험이 있다 — Round15 DECISION에서 이미
   확정한 "목적은 같으나 수치기법은 다르다"는 구분을 슬라이드 레벨에서도 유지해야 함.
2. **Abaqus 스크린샷의 배치**: 균열 전선 메시(F1~F21, collapse mesh, contour 1~8
   시각화)는 "FE 형상·BC" 슬라이드가 아니라 "해석조건" 슬라이드에 배치하는 것이
   벤치마크와 일치한다(벤치마크도 전체 형상 스케치는 BC 슬라이드에, 메시 확대컷은
   해석조건 슬라이드에 분리해서 배치).
3. **결과 그래프**: 벤치마크의 "일반눈금+log-log" 이중 스케일은 하중-반응량(J vs
   M_P/M_L)처럼 넓은 동적범위를 가진 양에 적합한 패턴이다. 사용자의 K vs 균열전선
   위치(F1~F21) 데이터는 동적범위가 좁아(448.8~487.0) log-log가 무의미하다. 대신
   벤치마크의 "Contour별 비교" 패턴(위 J-적분 자료의 Contour 1~10 비교)을 차용해
   **① Contour 1~8 전체를 위치별로 겹쳐 그린 그래프(지그재그 시각적 확인용), ②
   Contour_1 제외 후 평균±표준편차로 자유표면-중앙 분포를 보여주는 그래프** 2종을
   제시하는 것이 데이터 특성에 더 맞는 "이중 시각화"다.
4. **기호 정의 박스**: 벤치마크는 매 슬라이드 우상단에 그 슬라이드에서만 쓰는 기호를
   정의하는 작은 박스를 반복 배치한다. 기존 이론정리/결과분석 HTML은 본문 중간에
   기호를 설명하는 산문 형태라, 발표자료로 옮길 때는 이 패턴을 차용해 수식마다 옆에
   기호 박스를 붙이는 편집이 필요하다(내용은 이미 다 있음 — 재구성만 필요).

## C. 수준(level) 비교 — 체크리스트

| # | 기준 | 현재 상태 | 충족 여부 |
|---|---|---|---|
| 1 | 배경→목표→모델→결과→결론 흐름 연속성 | 4개 문서가 따로 존재, 통합 흐름 없음 | ✗ (A안대로 재배치하면 해결) |
| 2 | 모든 수치 주장에 출처/검증근거 | FE해석결과 분석 문서는 이미 각주·caveat 충실(Round15 기준 충족) | ✓ |
| 3 | 형상·경계조건 치수표+스케치 | **없음** — 시편 지간/폭/균열깊이 a 수치, 재료물성(E,ν) 수치가 현재 어떤 HTML에도 명시돼 있지 않음(grep 결과 "mm" 단위조차 0건) | ✗ (사용자가 가진 .cae 모델에서 직접 추출 필요 — Claude가 임의로 지어내면 안 됨) |
| 4 | 메시/요소타입/절점수 등 해석조건 구체성 | 요소타입(C3D20), contour 개수(8), crack-front 위치 수(21)는 이전 대화에서 확인됨. 단 element/node 총수는 미확인 | △ (TEST.dat/.cae에서 추가 추출 권장) |
| 5 | 결과 추출 시 이상치 제외 근거 | Contour_1 제외 근거(Abaqus 공식문서+벤치마크 Test 1.1 인용)는 이미 Round15 수준으로 충족, 벤치마크와 동일한 패턴 | ✓ |
| 6 | 결과의 2개 이상 시각화 | 현재 HTML 보고서에 **그래프/이미지가 전혀 삽입되어 있지 않음**(img 태그 0건, table 태그 0건) — 전부 산문+수식 텍스트 | ✗ (사용자의 2.png/3.png 그래프, Abaqus 스크린샷을 실제로 삽입해야 함) |
| 7 | 수식마다 기호 정의 동반 | 본문 서술형으로는 되어 있으나 벤치마크처럼 박스화되어 있지 않음 | △ |

**결론**: 이론적 내용(출처 신뢰성, caveat 처리, 이상치 제외 근거)은 이미 벤치마크
수준 이상으로 꼼꼼하지만, **시각 자료(표·그림)가 전무하다는 것이 가장 큰 격차**다.
벤치마크 자료들의 공통점은 모든 슬라이드에 최소 1개의 표 또는 그림이 있다는 것인데,
현재 사용자의 두 문서(이론정리, FE해석결과 분석)는 "교재형 설명 문서"로 작성되어
있어 그림이 전혀 없다. 발표자료로 전환 시 반드시 ① 시편 치수표, ② 재료물성표,
③ Abaqus 메시/균열전선 스크린샷, ④ 실제 K-위치 그래프(사용자가 이미 만든 2.png/
3.png 재사용 가능) 4종을 최소한 삽입해야 벤치마크와 동등한 수준이 된다고 판단한다.

## 확인 불가 사항
- 시편의 정확한 치수(지간, 폭 H, 균열깊이 a, 재료 E/ν 값)는 사용자의 .cae 파일에만
  있고 이전 대화에서 다뤄지지 않았음 — 지어내지 않음.
- element/node 총 개수는 TEST.dat 전체를 다시 열어야 확인 가능(이번 라운드 범위 밖).
