# 독립 검토: a/t 0.5 → 0.1 반경 방향 node morph 요구사항

INP 파일은 읽지 않았습니다. 아래는 지시문의 수치만으로 도출한 요구사항이며, 실제 파일로 확인한 결과가 아닙니다. 편집, 해석, fitting도 하지 않았습니다.

## 1. 기하 전제 (산술 확인)

- t = Ro − Ri = 60이고, a/t = 0.5이면 a = 30이므로 tip은 r = 300입니다.
- a/t = 0.1이면 a = 6이므로 tip은 r = 276입니다. 지시한 300 → 276과 일치합니다.
- 고정점은 f(270) = 270, f(300) = 276, f(330) = 330입니다.
- 구간 [270, 300]의 평균 기울기는 6/30 = 0.2이고, 구간 [300, 330]은 54/30 = 1.8입니다. 기울기가 약 9배 차이 납니다.
- Front 1과 Front 79(phi 90°)는 r = 300이고 Front 119는 r = 270입니다. Front 1~79가 r = 300 평탄 구간일 수 있으며, 이는 파일로 확인해야 합니다. 평탄 구간이 맞다면 tip line 전체가 기울기 불연속 위치에 놓입니다.

## 2. 사상 f(r) 요구사항

- 변환은 x' = x·f(r)/r, y' = y·f(r)/r, z' = z 형태로 θ와 z를 보존합니다. 축 위치(원점·z축)를 먼저 확인해야 합니다.
- f는 엄밀한 단조 증가(f' > 0)여야 하며 역사상이 존재해야 합니다. 그래야 node가 겹치거나 뒤집히지 않습니다.
- 위 세 고정점을 정확히 만족해야 합니다. 범위 [270, 330] 밖의 node가 있으면 extrapolation 금지 조건으로 걸러내야 합니다.
- 구간별 선형 사상은 단조이지만 r = 300에서 기울기가 0.2에서 1.8로 불연속입니다.
  - 이 지점은 tip line과 일치하므로, tip 주변 요소의 앞쪽(r > 300)은 1.8배로 늘어나고 뒤쪽은 0.2배로 줄어듭니다.
  - 그러면 J-contour ring이 비대칭으로 왜곡됩니다.
- 따라서 C¹ 이상의 단조 사상(PCHIP 등 단조 보간)을 권합니다. 전이 구간은 tip ring 바깥에 두고, tip ring 안에서는 f를 아핀(선형)으로 유지하는 것이 좋습니다.
  - 아핀 구간에서는 quarter-point node 위치가 보존됩니다. 비선형 구간에서는 midside node가 중점이나 1/4점에서 벗어납니다.
  - 아핀 구간에서 전단 구간으로 넘어갈 때의 기울기는 반드시 f' > 0이어야 합니다.
- f가 [270, 300]에서 선형이면 front 형상은 깊이 방향으로 정확히 0.2배가 됩니다. 비선형이면 front 형상이 원래 곡선의 단순 상사 변환이 되지 않으므로 별도 확인이 필요합니다.

## 3. Jacobian 및 무결성 검증 (사전·사후 비교)

1. 모든 C3D20R 요소에서 detJ > 0을 확인합니다. 확인 위치는 2×2×2 적분점, 8개 corner node, 12개 midside node입니다.
2. min detJ / max detJ와 요소별 종횡비, corner 각도를 사전·사후로 비교합니다. 임계값은 문헌값이 아니라 원본 mesh의 분포를 기준으로 잡아야 합니다. 원본보다 눈에 띄게 나빠진 요소를 목록으로 보고합니다.
3. 반경 방향 길이만 0.2배가 되고 θ·z 방향은 그대로이므로, 접합 요소의 종횡비가 약 5배까지 커질 수 있습니다. 특히 가장 얇은 요소가 어디인지 확인해야 합니다.
4. 전체 부피 보존을 확인합니다.
   - f가 [270, 330]을 자기 자신으로 보내는 전단사이므로, 영역 전체의 부피는 이론상 같아야 합니다.
   - 2차 요소 보간 오차 범위 안에서 사후 부피가 같은지 봅니다.
   - 어긋나면 사상 또는 node 누락을 의심합니다.
5. 균열면 중복 node 쌍은 같은 (x, y)에서 같은 결과가 나오므로 일치 상태가 유지되어야 합니다. 쌍별 거리가 허용오차 이내인지 확인합니다.
6. Ri 면과 Ro 면 node는 변하지 않아야 합니다. 좌표 오차의 상한을 확인합니다.
7. 요소 connectivity, NSET/ELSET 구성, *MATERIAL, *BOUNDARY, 하중 정의는 바이트 단위로 동일해야 합니다. *NODE 블록 외의 줄은 diff에서 한 줄도 달라지면 안 됩니다.
8. 좌표를 쓸 때는 유효숫자 8자리 이상을 쓰고, 변하지 않는 node는 원문 텍스트를 유지합니다.
9. alpha2와 source 파일은 수정하지 않습니다. 변경한 파일은 새 이름으로 저장하고 원본의 해시가 변하지 않았는지 확인합니다.

## 4. 균열 형상 한계 (사용자 판단 필요)

- θ와 z를 보존하면 표면 반길이 c는 그대로이고 깊이 a만 줄어듭니다. 따라서 a/c가 약 5배 작아집니다(f 선형 구간 기준).
- 얕고 긴 균열이 되며 표면점에서 front 접선 각도도 바뀔 수 있습니다. 이것이 의도된 형상인지 사용자 확인이 필요합니다. a/c를 유지하려면 θ·z 방향 변경이 필요한데 이는 지시와 충돌합니다.
- 사후에 a/t와 a/c를 front node 좌표에서 재계산해 보고합니다.
- 깊이 6 mm에 맞춰 tip ring의 외곽 반경이 충분히 작아야 합니다. 구체적인 수치 기준은 제가 확정할 수 없으며, 원본 ring 크기를 그대로 0.2배 한 값과 비교하라는 정도입니다.
- tip에 quarter-point 요소나 collapsed 요소가 있다면, 사후에 midside node가 1/4 위치에 있는지 확인하고 아니면 재조정해야 합니다.

## 5. 한계와 권고

- morph 후 요소 품질이 위 검증을 통과하지 못하면, morph를 억지로 쓰지 말고 재mesh를 권합니다.
- 해석 전 datacheck를 하면 Abaqus가 왜곡 요소 경고를 내 줍니다. 이는 solve가 아니지만 지시 범위 밖이므로 사용자 판단으로 남깁니다.
- 위 기준의 일부(종횡비, ring 크기 비율)는 문헌 근거가 아니라 일반적인 mesh 검증 관례입니다. 임계값은 원본 mesh를 기준선으로 삼아야 합니다.
